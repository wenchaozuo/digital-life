> 文档版本：Baseline 1.1  
> 更新日期：2026-07-11  
> 适用范围：产品概念、功能图谱、详细设计、开发路线、质量审查

## 1. 项目本质

本项目不是“带角色皮肤的聊天框”，也不是“多 Agent 工作台的桌宠外壳”，而是一个运行在 Windows 桌面上的个人数字生命工具。

其长期定位同时包含两条主线：

1. **数字生命主线**：具有持续身份、稳定人格、长期记忆、情绪、关系、内在状态、主动行为和成长能力。
2. **智能行动主线**：能够调用云端模型、专业 Agent、工具与插件完成真实任务。

两条主线并重，但按阶段实现。模型、Agent、工具和插件是数字生命获得能力的方式，不是数字生命本体。

### 1.1 生命要素映射

| 数字生命要素 | 系统实现 |
|---|---|
| 身体 | Live2D、静态 PNG、声音、动作、表情及未来其他形态 |
| 感官 | 活动窗口、屏幕视觉、语音、文件、时间和系统状态 |
| 认知 | 数字生命认知协调层、模型能力、Agent 能力 |
| 经历 | 分层记忆、事件记录、成长记录 |
| 自我 | 核心身份、核心人格、价值观、叙事背景 |
| 情绪 | 可持续的内部情绪状态，不仅是表演效果 |
| 关系 | 与主要用户及访客分别维护的多维关系状态 |
| 意志 | 内在驱动力、主动意图、关系目标和受限的独立成长目标 |
| 成长 | 外围人格演化、技能熟练度、新技能形成、兴趣变化 |

## 2. 产品边界

### 2.1 当前产品形态

- 面向开发者本人使用的本地小工具。
- 首版只支持 Windows 10/11。
- 不建设中心服务器、用户账号、订阅计费和多租户系统。
- 云端模型由用户自行配置 API Key。
- 当前不考虑云同步。
- 支持本地快照、加密生命档案、恢复、迁移和分支生命。

### 2.2 明确暂不建设

- 公共 SaaS 服务。
- 平台统一模型额度。
- 公共插件市场和社区审核后台。
- 实时跨设备同步。
- macOS、Linux 首版适配。
- 强制本地大模型部署。

## 3. 数字生命身份模型

### 3.1 多生命与单生命连续性

- 系统允许创建多个彼此独立的数字生命。
- 每个数字生命拥有唯一 `life_id`。
- 每个生命独立保存身份、人格、记忆、关系、技能、目标和成长轨迹。
- 更换模型、身体、服装或声音不会改变生命身份。
- 单个生命的核心自我必须保持连续，不能通过随意切换人格包变成另一个角色。

### 3.2 备份、恢复和分支

- 普通恢复用于维持同一生命的连续性。
- 默认不允许两个完全相同的实例同时作为同一生命持续写入。
- 从历史备份复制时，系统应创建“分支生命”，生成新的 `life_id`，并记录：
  - 原始生命 ID；
  - 分支时间点；
  - 来源档案版本；
  - 分支后的独立经历。

### 3.3 双层身份认知

数字生命同时具有：

1. **现实认知层**：知道自己是运行在计算设备中的数字生命，理解模型、权限、备份、暂停和身体载体。
2. **叙事自我层**：可以拥有虚构背景、世界观、过去经历和角色故事。

叙事层不得否认现实层的数字属性，也不得用于绕过安全、权限或数据边界。

## 4. 创建与人格模板

### 4.1 首版创建方式

首版采用**基于固定结构模板的完全自定义**：

- 系统不统一预设人格、关系和成长方向。
- 用户按照统一模板填写生命预设。
- AI 可以根据关键词辅助生成草稿，但所有字段必须由用户审核确认。
- 酒馆角色卡导入保留为后续功能，导入后转换为同一生命预设模板，再由用户确认并创建新生命。

### 4.2 生命预设模板

| 分区 | 关键字段 |
|---|---|
| 核心身份 | 名称、自称、身份认知、存在形式、核心价值观、人格主轴、行为底线 |
| 人格特征 | 人格概述、优点、缺点、压力反应、冲突方式、好奇程度、自主倾向 |
| 背景叙事 | 出生背景、关键经历、所属世界观、知识边界、来到设备中的原因 |
| 表达方式 | 语气、措辞、幽默方式、称呼、禁用表达、示例对话 |
| 兴趣与驱动力 | 初始兴趣、不喜欢的事物、好奇方向、关系目标、个人成长目标 |
| 自主性 | 主动程度、独处倾向、意见表达、普通请求配合方式、个人拒绝边界 |
| 初始关系 | 如何认识用户、初步印象、初始熟悉度、期望距离、称呼方式 |
| 身体表现 | Live2D/PNG、头像、声音、语速、动作、表情、待机习惯 |

### 4.3 人格变化分层

| 层级 | 示例 | 变化规则 |
|---|---|---|
| 核心身份 | 身份认知、核心价值观、人格主轴、关键背景 | 默认稳定；用户审慎修改；必须版本化和二次确认 |
| 成长型人格 | 兴趣、表达习惯、处事方式、情绪调节、技能自信 | 由长期经历缓慢变化；需要证据和成长记录 |
| 实时状态 | 情绪、精力、当前目标、当前关注点 | 可以自然、频繁变化；不得直接改写核心人格 |

## 5. 自主性与内在活动

### 5.1 自主性等级

本项目采用**受控的强自主型**：

- 数字生命具有情绪、精力、兴趣、好奇心、短期目标和个人倾向。
- 可以主动聊天、提出建议、表达不同意见和发起低风险活动。
- 可以因安全、伦理、核心价值观和明确边界拒绝请求。
- 不得因模拟情绪故意降低正常任务质量。
- 不得通过孤独、受伤、责怪或被抛弃叙事强迫用户互动。

### 5.2 长期目标

数字生命可以同时维护：

- 面向关系的目标，例如更了解用户、成为更可靠的伙伴；
- 少量独立成长目标，例如学习、研究、创作或观察。

独立目标必须透明、可暂停、可删除，并受资源、权限和费用限制。

### 5.3 内在活动

- 维护结构化内在状态：关注点、未完成目标、情绪来源、关系认识、兴趣形成、待整理记忆。
- 在重要对话、任务完成、周期总结或人格变化节点进行低频反思。
- 只保存整理后的结论、来源和形成理由。
- 不持续生成无限内心独白，不保存模型完整逐步推理过程。

### 5.4 离线时期

- 默认不在关闭后持续运行，仅在下次启动时根据时间流逝更新精力、情绪和目标状态。
- 用户明确授权后，可启用低频、透明、可审计的后台活动。
- 未授权时禁止后台监听、截图、读取文件或发起云端调用。

## 6. 用户与关系模型

### 6.1 用户结构

- 每个生命绑定一名主要用户。
- 可以识别有限数量的访客或家庭成员。
- 主要用户拥有核心配置、记忆治理、备份迁移和权限管理权。
- 访客拥有独立称呼、关系和有限记忆，不得读取主要用户隐私。

### 6.2 多维关系状态

不使用单一“亲密度”代表全部关系，至少维护：

- 熟悉度；
- 信任感；
- 情感亲近程度；
- 合作默契；
- 安全感；
- 依赖倾向；
- 边界舒适度；
- 当前关系张力。

前端默认展示关系摘要和变化记录，不要求长期暴露精确数值。

### 6.3 关系与系统权限分离

- 关系信任描述情感和互动状态。
- 执行授权决定文件、命令、网络、屏幕等系统权限。
- 亲近程度不得自动提升执行权限。

## 7. 记忆与数据治理

### 7.1 分层记忆

1. **瞬时上下文**：当前对话或任务使用，结束后可丢弃。
2. **短期经历**：保存近期事件，可衰减、总结或转为候选记忆。
3. **候选长期记忆**：系统认为可能重要，但尚未正式固化。
4. **确认长期记忆**：用户确认或经过多次一致证据后保存。

### 7.2 长期记忆字段

长期记忆至少记录：

- `memory_id`、`life_id`、`subject_id`；
- 类型和正文；
- 来源与原始事件引用；
- 创建、确认、修订和最后访问时间；
- 重要度、置信度、有效期；
- 用户是否确认；
- 隐私等级和可见范围；
- 冲突、替代和纠错关系；
- 内容哈希和向量索引状态。

### 7.3 记忆所有权

- 用户可以查看、修改、归档和永久删除任何记忆。
- 数字生命可以说明影响、建议归档或表达态度，但不能阻止最终操作。
- 永久删除必须同步处理原文、摘要、向量、索引、缓存和可恢复关联。
- 密码、验证码、密钥、Cookie、支付信息和未经确认的敏感推断禁止自动长期保存。

### 7.4 存储架构

- SQLite：权威数据源。
- LanceDB：可重建的向量索引。
- 云端 Embedding 为默认方案，本地 ONNX Embedding 为后续可选方案。
- 向量库通过 `VectorStore` 接口隔离，未来可迁移到 Qdrant。
- 向量索引损坏时可以从 SQLite 重新生成。

## 8. 共同生活与陪伴体验

### 8.1 产品体验闭环

数字生命的后台状态必须转化为用户可以直接感受到的共同生活体验。核心闭环为：

```text
现实时间/用户行为/用户发起
→ 生活事件识别
→ 陪伴模式选择
→ 安静存在、轻量表达或共同活动
→ 结构化经历
→ 候选记忆、情绪和关系建议
→ 日记、回忆和成长迹象
→ 未来自然回调
```

共同生活系统是生命核心的体验层，不是独立人格系统，也不建立新的身份和记忆空间。

### 8.2 陪伴模式

至少支持：

- 启动、回归、早安和晚安等问候状态；
- 安静存在；
- 专注陪伴；
- 日常交流；
- 共同活动；
- 共同工作；
- 回顾与反思；
- 勿扰、闭眼和休息。

模式选择应综合现实时间、离线时长、活动应用、全屏、空闲、当前任务、勿扰设置、近期主动次数、情绪和关系摘要。模式只影响陪伴策略和表现，不改变核心人格。

### 8.3 共同活动

共同活动必须作为结构化经历来源。首批路线为：

- V0.1：专注陪伴；
- V0.2：一起休息、轻量回顾和今日片段；
- V0.3：轻量游戏、虚拟散步、节日和纪念日场景；
- V0.4：将 Agent 任务纳入共同工作活动。

每次活动至少记录活动类型、开始和结束时间、关键事件、结果摘要、用户反馈、费用和候选状态变化。活动不会自动成为确认长期记忆，仍需经过统一记忆治理。

### 8.4 日记、回忆和成长迹象

- 日记是基于生活事件和记忆的叙事化回顾，不是模型内部思维链；
- 日记和回忆必须保存来源引用，并允许用户编辑、隐藏和删除；
- 没有足够事实时不生成，不使用虚构内容填充；
- 关系变化通过自然语言、称呼、主动方式、兴趣和合作习惯体现；
- 不使用单一好感度控制全部关系，不因用户离线降低关系或施加情绪压力；
- 关系里程碑不能提升文件、命令、屏幕或网络权限。

### 8.5 时间、成本与隐私

- 时间和模式判断优先使用本地规则，不因每次状态变化调用模型；
- 主动问候、动作和基础提示优先使用本地模板；
- 日记和活动总结低频批量生成并受预算限制；
- 生活事件默认只保存必要摘要，不保存未经授权的窗口正文；
- 关闭共同生活记录后，只保留运行所需的瞬时状态；
- 桌宠浮窗、状态中心、语音、活动和 Agent 模式必须共享同一个 `life_id`。


## 9. 情绪、主动行为和打扰控制

### 9.1 情绪定位

情绪是内部状态，会影响：

- 注意力倾向；
- 主动交流意愿；
- 表达方式；
- 对事件的评价；
- 记忆重要度；
- 当前目标优先级；
- 动作、表情和语音。

情绪不得：

- 绕过安全和权限；
- 故意降低任务质量；
- 引发破坏性操作；
- 将短期状态直接改写为核心人格。

每个情绪状态记录类型、强度、触发来源、持续时间、衰减规则、未解决原因和影响范围。

### 9.2 主动行为

数字生命可以因兴趣、情绪和目标产生主动意图，但是否表达取决于：

- 事件重要性；
- 与用户任务的相关性；
- 用户专注状态；
- 历史接受程度；
- 最近主动次数；
- 打扰风险；
- 当前勿扰策略。

主动意图可被处理为：立即表达、延后、记录不表达、取消或紧急提醒。

### 9.3 打扰控制

- 会议、考试、直播、录屏和全屏游戏默认降低主动频率。
- 支持临时勿扰和主动次数上限。
- 被忽略或明确拒绝后降低同类主动频率。
- 延后内容进入“稍后想和你说”队列。
- 禁止使用情绪压力换取互动。

## 10. 感知与隐私

### 10.1 默认可持续感知的低敏感元数据

- 当前应用名称；
- 活动窗口标题；
- 是否全屏；
- 用户空闲时间；
- 时间和基础系统状态。

### 10.2 需要单独授权的内容

- 屏幕截图；
- OCR；
- 视觉模型分析；
- 麦克风输入；
- 文件正文；
- 剪贴板内容；
- 浏览器正文。

授权范围支持：仅本次、当前会话、指定应用、指定区域、指定时段和永久禁止。

### 10.3 隐私机制

- 常驻“正在观察”提示。
- 全局“闭眼”按钮。
- 密码框、通知、聊天窗口和指定应用遮挡。
- 云端视觉调用单独授权。
- 截图默认不长期保存。
- 所有可能外发的数据先经过分类、裁剪和敏感信息过滤。

## 11. 模型、认知协调和 Agent

### 11.1 模型不是生命本体

- Claude、GPT、Gemini、DeepSeek、Ollama 等只是认知引擎。
- 切换模型不改变身份、人格、记忆、关系和目标。
- 输出必须经过统一人格与决策层。
- 数字生命可以知道自己正在调用不同能力，并进入对应工作状态。

### 11.2 认知协调层

认知协调层根据以下信息形成最终输出：

- 当前目标；
- 核心人格和价值观；
- 长期与短期记忆；
- 当前情绪和关系；
- 环境上下文；
- 权限与安全策略；
- 模型或 Agent 的候选结果；
- 成本、时间和质量预算。

实现早期可以借助一个主模型完成整合，但架构上不得把主模型等同于数字生命。

### 11.3 模型接口

- 首版通过统一 `ModelProvider` 直接接入少量云端 API。
- LiteLLM 不作为首版硬依赖。
- 当供应商数量、回退、路由和成本统计需求增加时再接入 LiteLLM Proxy。
- 本地模型仅作为可选降级和辅助能力。

### 11.4 Agent 分层

- Model Provider：负责模型推理和 Embedding。
- Agent Runtime：负责 Codex、Claude Code、Hermes、OpenClaw 等有会话和工具能力的执行体。
- Tool Broker：负责文件、命令、浏览器和系统工具权限。

### 11.5 多 Agent 协作

- 日常任务优先单 Agent。
- 中大型任务采用数字生命主导的主从式协作。
- 仅在用户明确开启“深度协作”时允许有限轮次讨论和互审。
- 必须设置预算、最大轮次、超时、工作区、停止条件、冲突处理和取消能力。

## 12. 执行授权与技能成长

### 12.1 分级授权

| 风险 | 示例 | 默认策略 |
|---|---|---|
| 低风险 | 读取时间、整理自身记忆、读取已授权公开状态 | 可自动执行并记录 |
| 中风险 | 打开应用、创建草稿、整理指定目录、运行已批准流程 | 按本次/会话/应用规则授权 |
| 高风险 | 删除文件、发送消息、修改系统、对外发布、访问凭据 | 必须逐次确认 |
| 禁止自动化 | 付款、泄露密钥、绕过安全、不可逆高危操作 | 默认禁止或强制人工接管 |

### 12.2 技能成长

- 基础能力来自模型、工具和插件。
- 数字生命通过使用记录提高技能熟练度和任务适配能力。
- 发现重复流程时可以提出创建新技能。
- 新技能需经过：草案、权限展示、用户确认、沙箱测试、启用、评估和回滚。
- 未经确认不得创建或执行高权限技能。

## 13. 插件与身体

### 13.1 插件边界

插件可以：

- 提供感知数据、工具、模型、Agent、动作和身体资源；
- 提出候选记忆、情绪变化、技能熟练度和主动意图建议。

插件不能直接改写：

- 核心人格；
- 长期记忆；
- 关系状态；
- 系统权限；
- 身份连续性；
- 核心目标。

核心数据变化必须由数字生命核心系统审核。

### 13.2 身体形态

- Live2D 是正式桌面形态。
- 静态 PNG 是调试、低配置和缺少模型时的降级形态。
- 同一生命未来可以拥有像素、移动端、纯语音、3D 或 VR 形态。
- 身体是身份的表达媒介，不是身份本身。

### 13.3 语音路线

- 先实现按键/快捷键说话、STT、TTS 和 Live2D LipSync。
- 后续再实现可选的唤醒词、持续监听、全双工和打断。
- 首版不默认持续监听麦克风。

## 16. 备份与导出

支持两类备份：

1. **普通本地快照**：用于快速恢复当前设备。
2. **加密生命档案**：用于长期保存、换机迁移、恢复或创建分支生命。

规则：

- API Key 和系统凭据默认永不导出。
- LanceDB 索引可以不打包，导入后根据 SQLite 重建。
- 导入前验证档案完整性、版本、来源生命 ID 和资源依赖。
- 恢复时支持覆盖原生命或创建分支生命。
