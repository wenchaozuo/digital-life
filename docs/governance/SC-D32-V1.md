## Approved PowerShell module-content admission V2 supersession

Under ADR-D32-POWERSHELL-MODULE-CONTENT-AUTHORITY-V2, the V1 PSHOME path-only assumption and blanket namespace-freeze proof are superseded. Before any installed-module import, the Coordinator must independently pin the exact path/SHA of a create-new `D32_POWERSHELL_MODULE_CONTENT_AUTHORITY_V2` schema-2 authority. It binds the exact clean candidate, canonical repository, Profile V2 and direct pinned PowerShell host, a complete finite PSHOME distribution inventory (file/directory identities, content hashes, owners and security descriptors), protected namespace policy, resolver policy and only the fixed Management → Utility → CimCmdlets closures. The generator remains module-free and may emit only an untrusted candidate.

The admitted run is unprivileged and accepts only explicitly trusted SYSTEM, TrustedInstaller or trusted elevated-administrator maintainers as namespace writers; the runner queries and records its process-token elevation/integrity, rejects elevated/high-integrity/system tokens and thread impersonation, and rechecks token state on reuse. No maintenance may occur during admission. Actual owner/ACL/token/lifecycle proof is required rather than inferring safety from a standard installation path. Retained handles prove object identity, not a whole-directory freeze. Any untrusted effective create/write/replace/delete/rename/reparse/attribute/DACL/owner ability, alias, reparse point, incomplete inventory or resolver candidate outside the pinned protected distribution and trusted Windows OS/CLR/Core base is BLOCKED. Possible resolver candidates must be covered by the complete protected inventory or rejected before use.

Before the first installed-module import, a fresh direct invocation of the exact pinned host with `-NoProfile -File <current exact runner>` and finite documented non-ambiguous switches must validate the true File operand, all independent caller pins and cross-bindings, content/identity/ACL/ancestor fences, startup state and managed/native resolver inputs using module-free Core/.NET. Autoload is disabled and PSModulePath is limited to the exact PSHOME Modules root. Only then may the three fixed manifests import in order; actual module, assembly, command and native origins are reconciled. Later library/phase reuse revalidates authority references, process/startup identity, content/ACL/identity fences and resolver policy. Wrappers, configuration/session/command modes, ambiguous or unknown switches, and relative/wrong File operands reject.

Every producer embeds a strict shared `D32_POWERSHELL_MODULE_ADMISSION_V2` schema-2 record in existing evidence, including actual runner token state; consumers, fixtures, nested references and gate readers reject V1, missing, prior, unknown, copied-as-own, stale or tampered records. Baseline V2 binds both the discovery producer admission and its distinct baseline producer admission. Outer schemas remain fixture provenance V7, discovery V2, baseline V2, Phase0 V8, release attestation V9 and aggregate V8. Profile V2, Trace V2, fixture manifest v3 and its six environment fields, bundle manifest v1, source/protoc/H7 authorities V1, owner marker, failure-only blocked-diagnostic V1, D31 seeder provenance V2 and Host consumption remain unchanged.

The former no-pin real-module SelfTest exception remains cancelled. No-pin checks must remain module-free and record `import_attempts=0`; they may not import modules, start children, run Cargo/network, claim a formal root or gate. Real SelfTest/LoaderSelfTest requires Profile and module-content admission before imports, and any mode-required Git/Profile pins must fail before import. Required positive evidence includes protected full-distribution and resolver proof, all three exact module closures/origins, reuse/cross-process admission and the full discovery→baseline→Phase0→release→aggregate chain. Required negatives include wrong/self-derived pins, schema/field errors, content/identity/ACL/dependency/namespace drift, reparse and startup injection, ambient/preloaded/shadow resolution, no-pin/forged/stale reuse, cross-process substitution and downstream omission/tampering. Use synthetic/record mutations only; never write to installed runtime files.
